# TermAlarm 仕様（刷新版）

2026年9月13日に全面刷新を決定した。旧仕様（純正時計アプリの代替を目指し、見た目も純正へ寄せる方針）は破棄する。
以前の内容はgitの履歴に残る。

## 刷新の理由

旧版は純正時計アプリの画面を実測し、寸法と配色と情報配置をそこへ寄せていた。
結果として「純正の作り直し」に見え、ストアに出せる独自性が無くなった。

似ていた原因は見た目だけではない。**製品としての立ち位置が純正と同じ**だったことが本体である。
アラーム・時計・タイマー・ストップウォッチを並列に並べた総合時計アプリという構成そのものを変える。

## 新しい立ち位置

**朝に弱い人のためのインターバルアラーム。**

- 主役は「開始時刻・終了時刻・間隔で繰り返し鳴らす」こと。これは純正に無い。
- 起きられない人を実際に起こすための仕掛けを、この主役の周りに集める。
- 時計・タイマー・ストップウォッチは、主役を支える**従属機能**として残す。並列のタブとしては扱わない。

| 項目 | 決定 |
|---|---|
| アプリ表示名 | TermAlarm（変更しない） |
| applicationId | `com.marutyan.termalarm`（変更しない） |
| 言語 | Kotlin |
| UI | Jetpack Compose |
| 配布 | Google Play |
| 検証 | JVM単体テスト + Compose UIテスト + adbによる実機確認 |

## 刷新の範囲

| 層 | 扱い |
|---|---|
| `domain/` | **残す。** Androidに依存しない計算とJVMテストは純正の意匠と無関係な資産。新機能のぶんを拡張する |
| `data/` | **作り直す。** 未公開のためデータ移行は不要。スキーマはversion 1から作り直す |
| `alarm/` `timer/` `stopwatch/` `notification/` | **仕組みは残す。** AlarmManagerの予約、全画面インテント、フォアグラウンドサービス、通知チャンネル、音量フェードインはOSとの接続部分であり、見た目とは独立している |
| `ui/` | **全部捨てて作り直す。** 画面構成、配色、タイポグラフィ、遷移をゼロから設計する |
| `docs/OFFICIAL_UI.md` `docs/OFFICIAL_SETTINGS.md` `docs/official-ui/` | **破棄する。** 純正の実測記録であり、刷新後に参照してはいけない |
| `design/` の既存モック | **破棄する。** 純正へ寄せた前提で作られている |

# 中核機能: インターバルアラーム

## 考え方

1件のアラームが「時刻の範囲」と「間隔」を持ち、1件で複数回鳴る。

例: 7:00〜9:00 を5分間隔 → 7:00, 7:05, ..., 9:00 の25回。

## 計算規則（旧仕様から変更なし）

```
span = if (endMinutes >= startMinutes) endMinutes - startMinutes
       else endMinutes + 1440 - startMinutes
```

鳴動時刻は、開始時刻から順に間隔を求めて積み上げる。回数を割り算で先に求めることはしない。
間隔が範囲の途中で変わる場合（後述）に、割り算では表せないため。

等間隔（開始間隔と終了間隔が同じ）の場合、結果は `span / interval + 1` 回と一致する。

- 開始と終了の**両端を含む**。
- `startMinutes == endMinutes` なら1回だけ（単発アラームに退化する）。
- `span` が間隔で割り切れない場合、最後の鳴動は `endMinutes` より前になる。
- 範囲が日をまたぐ場合（23:00〜01:00）、**セッションは開始日で1つ**と数える。
- 曜日の判定は**セッションの開始日**の曜日で行う。

## 予約の方式（旧仕様から変更なし）

- `AlarmManager` に登録するのは**常に次の1回だけ**。全回を一括登録しない。
- `setAlarmClock()` を使う。Doze中も発火し、ステータスバーに次のアラームが出る。
- 停止操作の直後に次の1回を再登録する。
- `BOOT_COMPLETED` / `LOCKED_BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` / `TIMEZONE_CHANGED` / `TIME_SET` / `LOCALE_CHANGED` で全予約を再計算する。

# 朝に弱い人のための機能（刷新の中心）

以下の4つが、このアプリを純正とも他のアラームアプリとも分ける部分である。
すべて**アラームごとに設定する**。平日の起床だけ厳しくし、昼寝は緩くする使い分けができる。

## 1. 解除チャレンジ

鳴動画面に問題を出し、正解するまで音が止まらない。

| 設定値 | 挙動 |
|---|---|
| `NONE` | 問題を出さない。押すだけで止まる |
| `LIGHT` | 毎回1問 |
| `HARD` | 範囲の進み具合に応じて1〜3問。終了時刻に近いほど増える |

出題は毎回ランダムに種類を選ぶ。同じ問題が続くと手が覚えて考えずに解けるため。

| 種類 | 内容 | 正解条件 |
|---|---|---|
| 計算 | 2桁の足し算・引き算 | 答えを入力して正解 |
| 順にタップ | ばらばらの 1〜12 を昇順に押す | 最後まで順番どおり |
| 書き写し | ランダムな英数字8文字を入力 | 完全一致 |
| 端末を振る | 加速度センサーで規定回数振る | 規定回数に到達 |
| 図形を数える | 混在する図形から指定の種類を数える | 個数が正解 |
| 色と文字 | 文字の意味と文字色が異なる語を出し、**文字色**を答えさせる | 選択肢から正解 |

- 「端末を振る」はセンサーの無い端末では出題しない。
- 判定は `domain/` の純粋関数に閉じ込め、画面は答えを整形して渡すだけにする。

### 安全弁（必須）

**チャレンジの設定にかかわらず、3秒の長押しで必ず止められる導線を鳴動画面に残す。**

理由: 会議中や人前で鳴った場合、問題を解けるまで止まらないのは実害が大きい。
解けない端末状態（手がふさがっている、画面が見づらい）もある。

- 長押し停止は「その回を止める」だけで、次回の予約は通常どおり行う。
- 長押し停止は起床記録に「緊急停止」として残す。実績の可視化で自分の傾向が分かる。
- 長押し停止は「今日はもう止める」ではない。両者を混同しない。

## 2. 間隔と音量の自動変化

範囲の終わりに近づくほど厳しくする。アラームごとに有効・無効を選ぶ。

### 間隔を短くする

`intervalMinutes` を1つの固定値ではなく、**開始間隔と終了間隔**で指定する。

- 進捗率 `p = (現在の鳴動時刻 - 開始時刻) / span`
- 次の間隔 = `startInterval + (endInterval - startInterval) * p` を分単位へ四捨五入（最低1分）
- 次の鳴動時刻 = 現在の鳴動時刻 + 次の間隔
- 次の鳴動時刻が終了時刻を超えたら、**その回を終了時刻へ置き換えて範囲を終える**

最後を終了時刻へ寄せるのは、終了時刻が「もう起きなければならない時刻」だからである。
等間隔のときは旧来どおり、割り切れなければ終了時刻より前で終わる（こちらは変えない）。

例: 7:00〜8:00、開始10分・終了3分 → 7:00, 7:10, 7:19, 7:27, 7:34, 7:40, 7:45, 7:50, 7:54, 7:58, 8:00（11回）

### 音量を上げる

- その回の音量上限 = `startVolume + (endVolume - startVolume) * p`
- 1回の鳴動の中で徐々に音量を上げる既存の動作（フェードイン）は残す。
  フェードインの**到達点**が、その回の上限になる。
- 音量は端末のアラーム音量に対する割合で持つ。端末の設定を超えない。

## 3. 起床確認

**範囲が終わった後に1回だけ**「本当に起きたか」を確認する。

- アラームごとに有効・無効。有効なら待ち時間を指定する（既定15分）。
- 範囲の最後の鳴動を停止してから待ち時間が経つと、確認の鳴動が1回だけ起きる。
- 確認の鳴動にも解除チャレンジが適用される（そのアラームの設定に従う）。
- 確認を停止すれば、そのセッションは完全に終わる。
- 「今日はもう止める」を実行した場合、確認は行わない。
- 範囲の途中で停止した回については確認しない。二度寝の検出は範囲の外で一度だけ行う。

範囲の中では間隔で鳴り続けるため、範囲内に確認を挟むと役割が重複する。だから範囲の外に1回だけ置く。

## 4. 起床記録と実績

端末の中だけに記録し、外部へは一切送らない。

### 記録する内容

鳴動1回ごとに:

| 項目 | 内容 |
|---|---|
| 予定時刻 | 鳴るはずだった時刻 |
| 停止時刻 | 実際に止めた時刻 |
| 停止方法 | チャレンジ正解 / 長押し緊急停止 / 自動消音（放置） |
| 何回目か | そのセッションの何回目の鳴動か |

セッション1つごとに:

| 項目 | 内容 |
|---|---|
| 開始日 | セッションの開始日 |
| 起床とみなした回 | 最後に停止した回。以降その日は鳴っていない |
| 起床までの所要時間 | 範囲の開始時刻から、起床とみなした回の停止時刻まで |
| 起床確認の結果 | 確認が鳴ったか、止めたか |

### 見せ方

- 直近7日と直近30日を切り替えて見る。
- 「何回目で起きたか」の推移と、「範囲の開始から何分で起きたか」の推移を出す。
- 長押し緊急停止の割合を出す。逃げ道の使いすぎに自分で気づけるようにする。

数字を良く見せるための加工はしない。放置して自動消音された回も、そのまま記録に残す。

# ウィジェット

ホーム画面に置く**時計ウィジェット**を1つ作る。Glance（Compose for Widgets）で実装する。

- 現在時刻を大きく、読みやすく出す。
- 次の鳴動時刻と、その時間帯の残り回数を一緒に出す（例: 「7:35 / あと23回」）。
- サイズを変えられる。小さいときは時刻と次の鳴動時刻だけにする。
- 鳴動中は、鳴っていることが分かる表示にする。

タイマーとロック画面向けのウィジェットは今回作らない。

## 残り回数の数え方（旧仕様から変更なし）

「あとN回」のNは、**現在鳴っている回を含まない**。

例: 7:00〜9:00 の5分間隔（全25回）で、いま7:05（2回目）が鳴っている場合、
次は7:10、7:10から9:00までは23回なので「あと23回」。

# 従属機能: 時計・タイマー・ストップウォッチ

残すが、主役ではない。純正と同じ機能一覧を揃えることを目的にしない。

## 時計

- アナログとデジタルを切り替えられる、秒まで見える時計。
- **世界時計は作らない。** 都市の追加・削除・並べ替え、時差表示、天気は入れない。
  （旧版に実装済みのコードがあるが、刷新で削除する）

## タイマー

- 時分秒を指定して開始。一時停止、再開、リセット、1分単位の延長。
- 複数を同時に動かせる。
- 画面を閉じても動き続ける。通知に残り時間を出す。
- 動作中はサービスを持たない。残り時間は通知の仕組みが数え、期限はAlarmManagerの予約で知る。
  鳴っている間だけサービスが立ち、音とバイブを担当する。
- 端末を再起動しても経過時間を復元して続ける。

## ストップウォッチ

- 開始、一時停止、再開、リセット、ラップ。
- 画面を閉じても、端末を再起動しても計測を続ける。

## 計測の精度

経過時間は `System.elapsedRealtime()` を基準にする。
端末の時刻設定やタイムゾーンが変わっても計測が飛ばないようにするため。

# デザイン

画面の構成は `/design` で合意した。配色は2案を出して選択待ち。

## 用語

**ターム**: 1件のアラームが持つ「開始時刻から終了時刻までの範囲」。
利用者はアラームを1件ずつ作るのではなく、タームを作る。画面の文言もこの語で統一する。

## 画面の構成

純正時計アプリのように4つのタブを横へ並べる形は取らない。

- 左端に細い縦のナビを置く。アラーム（ターム）、時計、タイマー、ストップウォッチ、記録。
- ホームは、いま何時か・進行中のタームがどこまで進んだか・起床の実績を1画面で見せる。
  横のタブを行き来しなくても、朝に必要な情報がそろう。
- 進行中のタームは大きなカードにする。時刻の範囲、曜日、鳴動の目盛、次の鳴動時刻を1枚に収める。
- 鳴動の目盛は、鳴り終わった回・いま鳴っている回・これからの回を塗り分ける。

## ミニマルモード

寝る前と起きた直後のために、記録もグラフも出さない表示モードを用意する。
いま何時か、次にいつ鳴るかだけを大きく出す。ホームとの切り替えは画面の右下に置く。

## 決めたこと

- **タームの名前は既定で付けない。** 名前を付けていないタームは、時刻の範囲そのものが見出しになる。
  名前を付けた場合だけ、範囲の上に出る。多くの人はタームを1つか2つしか作らないため、
  名前を必須にすると最初の入力が増えるだけになる。
- **タームのカードに曜日を出す。** 有効な曜日を塗り分けて7つ並べる。
  無効にしているタームでも、どの曜日のものかが分かる。
- **時刻の数字を大きく出す。** ホームは64px、鳴動画面は78px、ミニマルモードは124pxを目安とする。
  秒は小さく脇へ逃がす。

## 守る制約

- 純正時計アプリの画面を参照しない。実測値を写さない。
- 時刻の数字は等幅数字（tabular figures）を使う。桁が変わって幅が動くと鳴動画面がちらつくため。
- 明るいテーマと暗いテーマの両方で成立させる。
- 鳴動画面は、寝起きの人が迷わない情報量にする。

## フォント

| 用途 | フォント |
|---|---|
| 数字・ラテン文字 | Google Sans Flex（SIL OFL、可変フォント）を同梱 |
| 日本語 | 端末標準の日本語フォントへフォールバック。APKサイズを増やさないため同梱しない |

# データモデル

未公開のため、既存のデータを引き継ぐ移行処理は書かない。スキーマはversion 1から作り直す。

```kotlin
// アラーム1件。時刻の範囲と間隔を持ち、1件で複数回の鳴動を表す
data class AlarmSchedule(
    val id: Long,
    val startMinutes: Int,          // 0..1439。深夜0時からの経過分
    val endMinutes: Int,            // 0..1439。startMinutes と同値なら単発
    val startIntervalMinutes: Int,  // 1以上。範囲の始めの間隔
    val endIntervalMinutes: Int,    // 1以上。範囲の終わりの間隔。startと同値なら等間隔
    val repeatDays: Set<DayOfWeek>, // 空集合なら「次の1回だけ」
    val label: String,            // 既定は空。付けなければ画面には時刻の範囲だけが出る
    val soundUri: String?,          // null ならシステム既定のアラーム音
    val vibrate: Boolean,
    val enabled: Boolean,
    val challenge: ChallengeLevel,  // NONE / LIGHT / HARD
    val startVolumePercent: Int,    // 範囲の始めの音量上限。端末のアラーム音量に対する割合
    val endVolumePercent: Int,      // 範囲の終わりの音量上限。startと同値なら一定
    val wakeCheckMinutes: Int?,     // 範囲終了後の起床確認までの分数。null なら確認しない
    val skippedSessionStart: LocalDate?, // 「今日はもう止める」で終了させたセッションの開始日
)
```

`intervalMinutes` の単一値は `startIntervalMinutes == endIntervalMinutes` で表す。
同じ意味の値を2通りで持たない。

## 「今日はもう止める」

旧仕様の判断を引き継ぐ。

- 既定ではアプリを開かないと実行できない。鳴動画面には出さない。寝ぼけて押す事故を防ぐため。
- アラームごとに、鳴動画面へ出すことを許可できる。
- 実行前にチャレンジを挟むかどうかもアラームごとに選べる。
- 処理は `AlarmRepository` の1つの関数へ集約する。どの画面から呼んでも同じ規則を通す。

# 外部からの受け口

純正の代替を狙わなくなっても、次の受け口は実用上必要なので対応する。

| インテント | 用途 |
|---|---|
| `SET_ALARM` | 音声や他アプリから単発アラームを作る。開始と終了が同じアラームとして受ける |
| `SHOW_ALARMS` | アラーム一覧を開く |
| `DISMISS_ALARM` | 鳴っているアラームを止める |
| `SNOOZE_ALARM` | スヌーズする |

## 権限

```xml
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM" android:maxSdkVersion="32" />
<uses-permission android:name="android.permission.USE_EXACT_ALARM" />
```

`maxSdkVersion="32"` を付けるのは、API33以降で両方を宣言するとPlayの審査で不要な権限として扱われうるため。

`INTERNET` は宣言しない。このアプリは通信を行わない。

## 画面使用中の鳴動

画面を使用中にアラームが鳴ると、全画面ではなくヘッドアップ通知になる。Androidの標準の動作であり不具合ではない。

使用中も全画面で覆うには `SYSTEM_ALERT_WINDOW` が要るが、公式にアラームでの利用はベストプラクティス違反とされている。
**この判断を知らずに `SYSTEM_ALERT_WINDOW` を追加しないこと。**

# 検証

## JVM単体テスト（必須）

`domain/` はAndroidに依存しないため、必ずJVMテストを書く。

既存の検証項目を維持する。

- 両端を含む回数計算（7:00〜9:00 / 5分 → 25回）
- 割り切れない場合（7:00〜9:00 / 7分 → 最後は 8:59。7分×17回で119分後）
- 単発への退化（start == end → 1回）
- 日をまたぐ範囲（23:00〜01:00）と、曜日判定が開始日基準であること
- `repeatDays` が空のときの次回計算と、鳴り終わった後に null になること
- `skippedSessionStart` による当日スキップ

刷新で足す検証項目。

- 可変間隔の鳴動列が仕様どおりで、最後が終了時刻に一致すること
- 可変間隔で `startInterval == endInterval` のとき、等間隔の結果と完全に一致すること
- 間隔が1分を下回らないこと
- 進捗率に応じた音量上限の算出
- `HARD` のとき、進捗に応じて問題数が1〜3問に増えること
- 起床確認の時刻が「範囲の最後の鳴動の停止時刻 + 待ち時間」であること
- 「今日はもう止める」を実行したセッションでは起床確認が行われないこと
- 起床記録の集計（何回目で起きたか、所要時間、緊急停止の割合）

## 実機検証

実機へインストールして確認する。手順は `docs/DEVICE_TEST.md` に置く。

画面操作の自動化にGoogleのARTEMISを検討したが、実行するたびにLLMのAPI利用料が
かかるため見送った。実機の画面確認は `adb exec-out screencap` で行い、
画面の操作は Compose UIテスト（`app/src/androidTest/`）と手動で確認する。

実機UIテストは単体テストの実行ではコンパイルされない。`app/src/main/` の型を変えたときは
`./gradlew :app:compileDebugAndroidTestKotlin` も通すこと。一度、これを忘れて
実機確認ができない状態のままcommitしたことがある。

## 作らないもの

| 項目 | 理由 |
|---|---|
| 世界時計 | 主役から遠い。旧版のコードごと削除する |
| 天気・気温 | 通信と位置情報が必要になり、「通信しない」という性格が変わる |
| 祝日にスキップ | 祝日データの取得と維持が必要で、範囲が広がりすぎる |
| クラウド同期・アカウント | 通信しない方針と矛盾する |
| Wear OS対応 | 対象外 |
| スクリーンセーバー | 対象外 |
| ロック画面ウィジェット | 端末依存が大きい。今回は作らない |
| 将来用の抽象化層、複数実装のないinterface | 必要になってから作る |
