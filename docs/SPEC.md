# TermAlarm 仕様（刷新版）

2026年9月13日に全面刷新を決定した。旧仕様（純正時計アプリの代替を目指し、見た目も純正へ寄せる方針）は破棄する。
以前の内容はgitの履歴に残る。

## 刷新の理由

旧版は純正時計アプリの画面を実測し、寸法と配色と情報配置をそこへ寄せていた。
結果として「純正の作り直し」に見え、ストアに出せる独自性が無くなった。

似ていた原因は見た目だけではない。**製品としての立ち位置が純正と同じ**だったことが本体である。
アラーム・時計・タイマー・ストップウォッチを並列に並べた総合時計アプリという構成そのものを変える。

## 新しい立ち位置

**朝に弱い人のためのインターバルアラーム。**

- 主役は「開始時刻・終了時刻・間隔で繰り返し鳴らす」こと。これは純正に無い。
- 起きられない人を実際に起こすための仕掛けを、この主役の周りに集める。
- 時計・タイマー・ストップウォッチは、主役を支える**従属機能**として残す。並列のタブとしては扱わない。

| 項目 | 決定 |
|---|---|
| アプリ表示名 | TermAlarm（変更しない） |
| applicationId | `com.marutyan.termalarm`（変更しない） |
| 言語 | Kotlin |
| UI | Jetpack Compose |
| 配布 | Google Play |
| 検証 | JVM単体テスト + Compose UIテスト + adbによる実機確認 |

## 刷新の範囲

| 層 | 扱い |
|---|---|
| `domain/` | **残す。** Androidに依存しない計算とJVMテストは純正の意匠と無関係な資産。新機能のぶんを拡張する |
| `data/` | **作り直す。** 未公開のためデータ移行は不要。スキーマはversion 1から作り直す |
| `alarm/` `timer/` `stopwatch/` `notification/` | **仕組みは残す。** AlarmManagerの予約、全画面インテント、フォアグラウンドサービス、通知チャンネル、音量フェードインはOSとの接続部分であり、見た目とは独立している |
| `ui/` | **全部捨てて作り直す。** 画面構成、配色、タイポグラフィ、遷移をゼロから設計する |
| `docs/OFFICIAL_UI.md` `docs/OFFICIAL_SETTINGS.md` `docs/official-ui/` | **破棄する。** 純正の実測記録であり、刷新後に参照してはいけない |
| `design/` の既存モック | **破棄する。** 純正へ寄せた前提で作られている |

# 中核機能: インターバルアラーム

## 考え方

1件のアラームが「時刻の範囲」と「間隔」を持ち、1件で複数回鳴る。

例: 7:00〜9:00 を5分間隔 → 7:00, 7:05, ..., 9:00 の25回。

## 計算規則（旧仕様から変更なし）

```
span = if (endMinutes >= startMinutes) endMinutes - startMinutes
       else endMinutes + 1440 - startMinutes
```

鳴動時刻は、開始時刻から順に間隔を求めて積み上げる。回数を割り算で先に求めることはしない。
間隔が範囲の途中で変わる場合（後述）に、割り算では表せないため。

等間隔（開始間隔と終了間隔が同じ）の場合、結果は `span / interval + 1` 回と一致する。

- 開始と終了の**両端を含む**。
- `startMinutes == endMinutes` なら1回だけ（単発アラームに退化する）。
- `span` が間隔で割り切れない場合、最後の鳴動は `endMinutes` より前になる。
- 範囲が日をまたぐ場合（23:00〜01:00）、**セッションは開始日で1つ**と数える。
- 曜日の判定は**セッションの開始日**の曜日で行う。

## 予約の方式（旧仕様から変更なし）

- `AlarmManager` に登録するのは**常に次の1回だけ**。全回を一括登録しない。
- `setAlarmClock()` を使う。Doze中も発火し、ステータスバーに次のアラームが出る。
- 停止操作の直後に次の1回を再登録する。
- `BOOT_COMPLETED` / `LOCKED_BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` / `TIMEZONE_CHANGED` / `TIME_SET` / `LOCALE_CHANGED` で全予約を再計算する。

# 朝に弱い人のための機能（刷新の中心）

以下の4つが、このアプリを純正とも他のアラームアプリとも分ける部分である。
すべて**アラームごとに設定する**。平日の起床だけ厳しくし、昼寝は緩くする使い分けができる。

## 1. 解除チャレンジ

鳴動画面に問題を出し、正解するまで音が止まらない。

**いつ出すか**と**どれだけ厳しいか**を分けて選ぶ。この2つは別の話であり、
1つの選択肢へまとめると「終了時だけ厳しく」のような組み合わせが選べなくなる。

いつ出すか（`challengeTiming`）

| 設定値 | 挙動 |
|---|---|
| `NEVER` | 問題を出さない。押すだけで止まる |
| `END_ONLY` | ターム終了時の1回だけ問題を出す。途中は押すだけで止まる |
| `EVERY_TIME` | 鳴るたびに問題を出す |

どれだけ厳しいか（`challenge`）。画面には「Easy」「Hard」と出す。

| 設定値 | 挙動 |
|---|---|
| `EASY` | 1問 |
| `HARD` | 範囲の進み具合に応じて1〜3問。終了時刻に近いほど増える |

`challengeTiming` が `NEVER` のとき、`challenge` は使われない。

出題は毎回ランダムに種類を選ぶ。同じ問題が続くと手が覚えて考えずに解けるため。
どの種類を使うかは設定で選ぶ。既定は「歩く」以外すべて有効。

### なぜ種類を増やすのか

他のアラームアプリを調べたところ、この仕組みがうまくいかない一番の原因は
**問題の種類ではなく「慣れ」**だった。

- Sleep as Android の公式フォーラムに「最高難易度でも完全に目覚めずに解ける」という
  利用者の報告があり、開発元も同意している。
- 「3か月同じ計算をやると、多くの利用者は半覚醒で解いてそのまま二度寝できる」という
  指摘がある。
- QRコードを読ませる方式でも「頭を使わないので読んだあとベッドに戻って寝た」という報告がある。

だから、**種類を多く持ち、毎回ちがうものが出ること**そのものが対策になる。
1回の停止で複数問を出す仕組み（`HARD`）も同じ目的を持つ。

### 種類

| 種類 | 内容 | 正解条件 |
|---|---|---|
| 計算 | 四則演算 | 答えを入力して正解 |
| 順にタップ | ばらばらの 1〜12 を昇順に押す | 最後まで順番どおり |
| 書き写し | ランダムな英数字8文字を入力 | 完全一致 |
| 鏡文字 | 左右反転した英数字を読み取って入力 | 完全一致 |
| 光った順を再現 | 光った順にタップし直す。長さが伸びる | 最後まで順番どおり |
| 神経衰弱 | 3×4の伏せ札からペアをそろえる | 全部そろう |
| 図形を数える | 混在する図形から指定の種類を数える | 個数が正解 |
| 色と文字 | 文字の意味と文字色が異なる語を出し、**文字色**を答えさせる | 選択肢から正解 |
| 端末を振る | 加速度センサーで規定回数振る | 規定回数に到達 |
| 歩く | 端末を持って規定の歩数だけ歩く | 規定歩数に到達 |

- 「端末を振る」と「歩く」はセンサーの無い端末では出題しない。
- **「歩く」は既定で無効**にする。ベッドから出る必要があり最も効くが、数十秒では終わらない。
  必要な人が設定で有効にする。
- 歩数は加速度センサーから自前で数える。`ACTIVITY_RECOGNITION` 権限を足さないため。
- **「端末を振る」は軽い。** 布団の中の小さな動きで終わるため、これだけを有効にしない
  ように画面で促す。他のアプリの開発元自身が「入門用」と位置づけている。
- 判定は `domain/` の純粋関数に閉じ込め、画面は答えを整形して渡すだけにする。

### 作らないもの

| 種類 | 理由 |
|---|---|
| 写真を撮る、QRコードを読む | カメラ権限が要る。効果は最も高いが、権限に見合わないと判断した |
| 笑顔を見せる | カメラ権限に加え、**認識に失敗して止められなくなる事故が他アプリで実際に起きている** |
| 声を出す | マイク権限が要る |
| 回転する、光にかざす | コンパスや照度センサーが要る。機種によって反応しない報告がある |
| スクワット | 加速度センサーで作れるが、他アプリでも検出の不具合が繰り返し直されている。寝起きで「判定されない」と詰む |
| 国旗当て、首都と国名 | 知識に依存し、知らない人が毎朝詰む |

### 鳴動画面の操作

鳴動画面の主な操作は「ストップ」1つ。今回の鳴動を止め、次の時刻にまた鳴る。

「タームを終了」のボタンも置くが、**鳴動画面では終了させない。** 押すとアプリが開き、
確認画面で改めて実行する。寝ぼけたまま鳴動画面で完結させると、その日の残り全部が
消えるため。ボタンを置くのは、終了する手段があること自体を知らせるため。

3秒長押しの緊急停止も作らない。隠れた操作は覚えてもらえない。
会議中などに鳴った場合の逃げ道は、問題を出さない設定か `END_ONLY` が担う。

## 2. 間隔の自動変化

範囲の終わりに近づくほど間隔を短くする。タームごとに「等間隔」か「加速」を選ぶ。

### 加速（終わりに向けて間隔を短くする）

`intervalMinutes` を1つの固定値ではなく、**開始間隔と終了間隔**で指定する。

- 進捗率 `p = (現在の鳴動時刻 - 開始時刻) / span`
- 次の間隔 = `startInterval + (endInterval - startInterval) * p` を分単位へ四捨五入（最低1分）
- 次の鳴動時刻 = 現在の鳴動時刻 + 次の間隔
- 次の鳴動時刻が終了時刻を超えたら、**その回を終了時刻へ置き換えて範囲を終える**

最後を終了時刻へ寄せるのは、終了時刻が「もう起きなければならない時刻」だからである。
等間隔のときは旧来どおり、割り切れなければ終了時刻より前で終わる（こちらは変えない）。

例: 7:00〜8:00、開始10分・終了3分 → 7:00, 7:10, 7:19, 7:27, 7:34, 7:40, 7:45, 7:50, 7:54, 7:58, 8:00（11回）

### 音量はタームごとに持たない

鳴動の音量は端末のアラーム音量に従う。タームごとの音量設定は作らない。
端末の音量設定と二重になり、どちらが効いているのか分からなくなるため。

1回の鳴動の中で徐々に音量を上げる動作だけを、アプリ全体の設定として持つ
（`AppSettings.alarmFadeInSeconds`）。純正の時計アプリと同じ考え方。

## 3. 二度寝チェック

**ターム終了後に1回だけ**、二度寝をしていないかを確かめる。画面には「二度寝チェック」と出す。

- アラームごとに有効・無効。有効なら待ち時間を指定する（既定15分）。
- 範囲の最後の鳴動を停止してから待ち時間が経つと、確認の鳴動が1回だけ起きる。
- 確認の鳴動にも解除チャレンジが適用される（そのアラームの設定に従う）。
- 確認を停止すれば、そのセッションは完全に終わる。
- 「タームを終了」を実行した場合、確認は行わない。
- 範囲の途中で停止した回については確認しない。二度寝の検出は範囲の外で一度だけ行う。

範囲の中では間隔で鳴り続けるため、範囲内に確認を挟むと役割が重複する。だから範囲の外に1回だけ置く。

## 4. 起床記録と実績

端末の中だけに記録し、外部へは一切送らない。

### 記録する内容

鳴動1回ごとに:

| 項目 | 内容 |
|---|---|
| 予定時刻 | 鳴るはずだった時刻 |
| 停止時刻 | 実際に止めた時刻 |
| 停止方法 | 問題に正解 / 押して停止 / 自動消音（放置） |
| 何回目か | そのセッションの何回目の鳴動か |

セッション1つごとに:

| 項目 | 内容 |
|---|---|
| 開始日 | セッションの開始日 |
| 起床とみなした回 | 最後に停止した回。以降その日は鳴っていない |
| 起床までの所要時間 | 範囲の開始時刻から、起床とみなした回の停止時刻まで |
| 二度寝チェックの結果 | チェックが鳴ったか、止めたか |

### 見せ方

- 直近7日と直近30日を切り替えて見る。
- 「何回目で起きたか」の推移と、「範囲の開始から何分で起きたか」の推移を出す。
- 放置して自動で鳴り止んだ割合を出す。二度寝の多さに自分で気づけるようにする。

数字を良く見せるための加工はしない。放置して自動消音された回も、そのまま記録に残す。

# ウィジェット

ホーム画面に置く**時計ウィジェット**を1つ作る。Glance（Compose for Widgets）で実装する。

- 現在時刻を大きく、読みやすく出す。
- 次の鳴動時刻と、その時間帯の残り回数を一緒に出す（例: 「7:15 / あと22回」）。
- サイズを変えられる。小さいときは時刻と次の鳴動時刻だけにする。
- 時刻を大きく中央に置き、その上に日付と曜日、下に次に鳴る時刻を小さく添える。
  大きいほうは残り回数も出す。
- **背景・文字・色を選べる。**
  - 背景: 無地 / 透明。透明は壁紙の上に文字だけが乗るため、読めるように文字へ薄い影を付ける
  - 文字: 数字の書体を数種類から選ぶ
  - 色: 紺 / 黒 / 端末の色。アプリ本体の配色とは別に選べる
- 鳴動中は、鳴っていることが分かる表示にする。

タイマーとロック画面向けのウィジェットは今回作らない。

## 残り回数の数え方（旧仕様から変更なし）

「あとN回」のNは、**現在鳴っている回を含まない**。

例: 7:00〜9:00 の5分間隔（全25回）で、いま7:05（2回目）が鳴っている場合、
次は7:10、7:10から9:00までは23回なので「あと23回」。

# 従属機能: 通常アラーム・タイマー・ストップウォッチ

残すが、主役ではない。純正と同じ機能一覧を揃えることを目的にしない。

## 通常アラーム

1回だけ鳴る、ふつうのアラーム。専用の欄を持つ。

タームは「範囲と間隔」を前提にしているため、単発のアラームを作りたいときに
開始と終了へ同じ時刻を入れさせるのは分かりにくい。画面を分けて、単発は単発として扱う。

データは `AlarmSchedule` をそのまま使い、開始と終了が同じものを通常アラームとして並べる。
同じ意味のモデルを2つ持たない。`SET_ALARM` インテントで作られたものもこの欄に並ぶ。

## 時計の欄は作らない

ホームに現在時刻を大きく出しているため、同じものを別の欄へ置く意味がない。
世界時計も作らない。旧版に実装済みの世界時計とアナログ時計のコードは、刷新で削除する。

## タイマー

- 時分秒を指定して開始。一時停止、再開、リセット、1分単位の延長。
  リセットは動作中も一時停止中も使える。
- 複数を同時に動かせる。
- 画面を閉じても動き続ける。通知に残り時間を出す。
- 動作中はサービスを持たない。残り時間は通知の仕組みが数え、期限はAlarmManagerの予約で知る。
  鳴っている間だけサービスが立ち、音とバイブを担当する。
- 端末を再起動しても経過時間を復元して続ける。

## ストップウォッチ

- 開始、一時停止、再開、リセット、ラップ。
- 画面を閉じても、端末を再起動しても計測を続ける。

## 計測の精度

経過時間は `System.elapsedRealtime()` を基準にする。
端末の時刻設定やタイムゾーンが変わっても計測が飛ばないようにするため。

# デザイン

画面の構成と配色は `/design` で合意した。

## 用語

**ターム**: 1件のアラームが持つ「開始時刻から終了時刻までの範囲」。
利用者はアラームを1件ずつ作るのではなく、タームを作る。画面の文言もこの語で統一する。

## 配色

既定はアプリアイコンから取った紺。設定で明るい配色、黒、「端末の色」も選べる。

「端末の色」は、Androidが壁紙から作る色（ダイナミックカラー）を使う。
端末の他のアプリと調和し、利用者が壁紙を変えると一緒に変わる。

| 役割 | 紺（既定） | 明るい | 黒 |
|---|---|---|---|
| 画面の地 | `#0B1530` | `#F5F7FB` | `#0A0A0A` |
| カードの地 | `#142449` | `#FFFFFF` | `#111111` |
| 主役の色 | `#8CDDC2` | `#0B7A64` | `#A3E635` |
| 注意の色 | `#FEE48F` | `#B54708` | `#F59E0B` |
| 本文 | `#E8EEF9` | `#101828` | `#E5E5E5` |
| 副次の文字 | `#A9C0E4` | `#475467` | `#A3A3A3` |
| 薄い文字 | `#8AA0C9` | `#5D6B82` | `#858585` |

どの配色でも、文字と背景のコントラストは4.5:1以上を保つ。
明るい配色の主役の色は、そのままでは基準に届かなかったため暗くしてある。

紺はアイコンと揃うため、ホーム画面に置いたときに同じアプリだと分かる。
黒は有機ELで消費電力が下がり、暗い部屋でまぶしくない。どちらを好むかは分かれるため設定で選ぶ。

配色は `AppSettings` の `theme`（`NAVY` / `LIGHT` / `BLACK` / `DYNAMIC`）として保存する。
`DYNAMIC` はAndroid 12以降でだけ選べる。それより前の端末では選択肢に出さない。
domain には色の値を持たせない。enumだけを持ち、実際の色は画面側で解決する。

## 画面の構成

純正時計アプリのように4つのタブを横へ並べる形は取らない。左端に細い縦のナビを置く。
ターム、通常アラーム、記録、タイマー、ストップウォッチの5つと、いちばん下に設定。

### ホーム

上から順に読める並びにする。朝に必要なものだけを置き、統計は出さない。

1. いまの時刻。秒は時刻のすぐ隣へ小さく添える
2. つぎに鳴る時刻。いまの時刻と同じ大きさで出す
3. そのタームの範囲と間隔、残り回数
4. 鳴動の目盛。鳴り終わった回・いま鳴っている回・これからの回を塗り分ける
5. タームのカード一覧と「タームを追加」

### 記録

起床の実績はホームから分け、専用の画面へ置く。
平均で何回目に起きたか、範囲開始から何分かかったか、放置して鳴り止んだ回がどれだけあるか。
期間は直近7日と直近30日を切り替える。日ごとの一覧も出す。

数字を良く見せるための加工はしない。起きられなかった日もそのまま残す。

### ターム編集

下から持ち上がるシートで開く。画面の7割ほどに収め、背後にホームが見えるようにする。
上から「いつ鳴らすか（時刻の範囲と曜日）」「どう鳴らすか（間隔と問題の出題）」
「その他（二度寝チェック、名前、音、バイブ）」の順に並べる。

間隔は「等間隔」と「加速」から選ぶ。加速を選んだときだけ、はじめとおわりの分数を出す。
実際に鳴る時刻は全部並べず、最初の3つと最後の2つ、それに全部で何回かを出す。
全部並べても読まれないうえ、シートが縦に伸びる。

### タームのカード

横長の1行にまとめる。左端に有効・無効が分かる色の帯、時刻の範囲、曜日、間隔と回数、
右端に有効・無効の切り替え。無効にしているタームでも、どの曜日のものかが分かる。

## 決めたこと

- **タームの名前は既定で付けない。** 名前を付けていないタームは、時刻の範囲そのものが見出しになる。
  名前を付けた場合だけ、範囲の上に出る。多くの人はタームを1つか2つしか作らないため、
  名前を必須にすると最初の入力が増えるだけになる。
- **タームのカードに曜日を出す。** 有効な曜日を塗り分けて7つ並べる。
  無効にしているタームでも、どの曜日のものかが分かる。
- **時刻の数字は、いまの時刻を主役にする。** ホームの現在時刻は78px、
  次に鳴る時刻は44pxとし、次に鳴る時刻には主役の色を乗せる。
  同じ大きさで2つ並べると、どちらが現在時刻か分からなくなる。
  大きさで順位を付け、色で注意を引く。鳴動画面の時刻は86px。
  秒は現在時刻のすぐ隣へ27pxで添える。離れた位置に置くと読みにくい。
- **週は月曜から始める。** タームの曜日も、記録の週ごとの並びも月曜始まりにする。
- **押しやすさを優先する。** 寝起きの指で操作するため、押せるものを小さくしない。
  タームのカードは高さ100px前後とし、行のどこを押しても編集へ入る。曜日の丸は26px、
  有効・無効の切り替えは40×24px、「タームを追加」は高さ52px、
  鳴動画面のチャレンジのタイルは3列にして78px角とする。

## 守る制約

- 純正時計アプリの画面を参照しない。実測値を写さない。
- 時刻の数字は等幅数字（tabular figures）を使う。桁が変わって幅が動くと鳴動画面がちらつくため。
- 鳴動画面は、寝起きの人が迷わない情報量にする。

## 読みやすさと操作しやすさの基準

Appleのヒューマンインターフェイスガイドラインが示す数値に合わせる。Androidアプリだが、
これらは特定のプラットフォームに依らない基準であり、根拠となる数値が公開されている。

| 項目 | 基準 | 理由 |
|---|---|---|
| 文字の最小サイズ | 11sp | これより小さい文字は読めない人が出る |
| 文字のコントラスト | 17sp以下は4.5:1以上、18sp以上または太字は3:1以上 | WCAG Level AAの基準 |
| 文字でない要素のコントラスト | 3:1以上 | アイコンや区切り線が背景に溶けないため |
| 押せるものの当たり判定 | 44dp × 44dp以上 | 見た目が小さくても判定は広げる |
| 押せるもの同士の間隔 | 枠のある要素で12dp以上 | 隣を押してしまうのを防ぐ |
| 文字の拡大 | 200%まで崩れないこと | 端末の文字サイズ設定に従う |

### 文字の拡大に耐える作り

端末の文字サイズを大きくしたとき、次のようにする。高さを固定した箱に文字を押し込まない。

- 横に並べた要素は、入りきらなければ縦へ積み替える。
- カードや行の高さは中身に合わせて伸びるようにする。
- 1行の想定でも、必要なら複数行へ伸ばす。文字を省略記号で切るのは最後の手段にする。
- ターム編集のシートは、文字が大きいときは全画面へ切り替える。

### 色だけで情報を伝えない

選ばれている曜日、選ばれている選択肢、オンになっている切り替えは、色の違いだけでなく
塗りの有無や文字色の反転といった形の違いも併せて示す。
色の見え方には個人差があり、屋外の強い光の下では色が沈んで見えるため。

### シートの扱い

ターム編集のシートには、保存とは別に閉じる操作を必ず置く。
保存しかないと、間違えて開いたときに出口が無い。
端末の戻る操作でも閉じられるようにし、保存していない変更があるときは確認する。

## フォント

デザインで使った書体をそのまま実装へ持ち込む。数字の形がこのアプリの印象を作っているため。

| 用途 | フォント |
|---|---|
| 数字 | IBM Plex Mono |
| ラテン文字と記号 | IBM Plex Sans |
| 日本語 | 端末標準の日本語フォントへフォールバック。同梱しない |

- **同梱するのは IBM Plex Mono の可変フォント1つだけ。** `IBM Plex Mono Var-Roman.ttf`、
  約200KB。SIL OFL で同梱に制限はない。ライセンス本文もアプリへ含め、
  「このアプリについて」から読めるようにする。
- **IBM Plex Sans は同梱しない。** 画面の文章はほとんどが日本語で、日本語は端末標準へ
  フォールバックする。Sans が担うのは「Easy」「Hard」のようなわずかなラテン文字だけで、
  そのために500KB以上を足す価値がない。そこは端末標準の書体に任せる。
- **可変フォントを使う。** 太さを200から500まで使い分けるが、ウェイトごとにファイルを
  持つとAPKが大きくなる。可変フォントは Android 8.0 以降で使え、minSdk 26 を満たす。
- サブセット化はしない。200KBは許容できる大きさで、絞るために外部のツールを足すと
  ビルドの手順が増える。
- 時刻の数字は等幅数字（tabular figures）を使う。IBM Plex Mono は等幅なので既定で満たす。

# データモデル

未公開のため、既存のデータを引き継ぐ移行処理は書かない。スキーマはversion 1から作り直す。

```kotlin
// アラーム1件。時刻の範囲と間隔を持ち、1件で複数回の鳴動を表す
data class AlarmSchedule(
    val id: Long,
    val startMinutes: Int,          // 0..1439。深夜0時からの経過分
    val endMinutes: Int,            // 0..1439。startMinutes と同値なら単発
    val startIntervalMinutes: Int,  // 1以上。範囲の始めの間隔
    val endIntervalMinutes: Int,    // 1以上。範囲の終わりの間隔。startと同値なら等間隔
    val repeatDays: Set<DayOfWeek>, // 空集合なら「次の1回だけ」
    val label: String,            // 既定は空。付けなければ画面には時刻の範囲だけが出る
    val enabled: Boolean,
    val challengeTiming: ChallengeTiming, // NEVER / END_ONLY / EVERY_TIME
    val challenge: ChallengeLevel,  // EASY / HARD。timingがNEVERなら使わない
    val wakeCheck: Boolean,         // ターム終了後に二度寝チェックを行うか
    val skippedSessionStart: LocalDate?, // 「タームを終了」で終了させたセッションの開始日
)

タームが持つのは「いつ・どれだけの頻度で鳴らすか」と「どう止めさせるか」だけにする。
音、バイブ、二度寝チェックまでの分数のように、**タームごとに変える意味が薄いものは
アプリ全体の設定へ置く**。タームの編集画面を短く保つため。

## アプリ全体の設定

```kotlin
// アプリ全体の設定。タームごとに変える意味が薄いものをここへ集める
data class AppSettings(
    val alarmSoundUri: String?,      // null ならシステム既定のアラーム音
    val vibration: Boolean,          // 鳴動時に振動するか
    val fadeInSeconds: Int,          // 1回の鳴動の中で音量を上げきるまでの秒数
    val silenceAfterMinutes: Int?,   // 放置したとき自動で止まるまでの分数。null なら止めない
    val wakeCheckMinutes: Int,       // ターム終了後、二度寝チェックまでの分数。既定5
    val enabledGames: Set<GameKind>, // 出題に使うミニゲームの種類
    val theme: AppTheme,             // NAVY / LIGHT / BLACK / DYNAMIC
)
```

`silenceAfterMinutes` の既定は `null`（自動で止めない）。
止めるまで鳴り続けるのが、朝に弱い人のためのアラームとして素直なため。

**スヌーズは作らない。** 範囲と間隔で繰り返し鳴る仕組みが、スヌーズの役割をすでに果たす。
5分間隔なら止めても5分後に鳴るため、5分スヌーズは次回の鳴動と重なって意味を持たない。
`SNOOZE_ALARM` インテントを受けた場合は、その回を止めるだけにする。
```

`intervalMinutes` の単一値は `startIntervalMinutes == endIntervalMinutes` で表す。
同じ意味の値を2通りで持たない。

## 「タームを終了」

その日のタームを、範囲の途中でも終わらせる操作。**アプリを開いたときだけ実行できる。**

入り口はホームの進行中タームの下に置き、押すと確認を出す。
確認では、終わるのが今日の分だけであること、二度寝チェックも行わないことを示す。

- 寝ぼけて押す事故は、問題を出す設定（`END_ONLY` または `EVERY_TIME`）で防ぐ。
  問題に正解しないとタームは終わらない。
- 処理は `AlarmRepository` の1つの関数へ集約する。どの画面から呼んでも同じ規則を通す。

# 外部からの受け口

純正の代替を狙わなくなっても、次の受け口は実用上必要なので対応する。

| インテント | 用途 |
|---|---|
| `SET_ALARM` | 音声や他アプリから単発アラームを作る。開始と終了が同じアラームとして受ける |
| `SHOW_ALARMS` | アラーム一覧を開く |
| `DISMISS_ALARM` | 鳴っているアラームを止める |
| `SNOOZE_ALARM` | 受けるが、スヌーズは作らないため、その回を止めるだけにする |

## 権限

```xml
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM" android:maxSdkVersion="32" />
<uses-permission android:name="android.permission.USE_EXACT_ALARM" />
```

`maxSdkVersion="32"` を付けるのは、API33以降で両方を宣言するとPlayの審査で不要な権限として扱われうるため。

`INTERNET` は宣言しない。このアプリは通信を行わない。

## 画面使用中の鳴動

画面を使用中にアラームが鳴ると、全画面ではなくヘッドアップ通知になる。Androidの標準の動作であり不具合ではない。

使用中も全画面で覆うには `SYSTEM_ALERT_WINDOW` が要るが、公式にアラームでの利用はベストプラクティス違反とされている。
**この判断を知らずに `SYSTEM_ALERT_WINDOW` を追加しないこと。**

# 検証

## JVM単体テスト（必須）

`domain/` はAndroidに依存しないため、必ずJVMテストを書く。

既存の検証項目を維持する。

- 両端を含む回数計算（7:00〜9:00 / 5分 → 25回）
- 割り切れない場合（7:00〜9:00 / 7分 → 最後は 8:59。7分×17回で119分後）
- 単発への退化（start == end → 1回）
- 日をまたぐ範囲（23:00〜01:00）と、曜日判定が開始日基準であること
- `repeatDays` が空のときの次回計算と、鳴り終わった後に null になること
- `skippedSessionStart` による当日スキップ

刷新で足す検証項目。

- 可変間隔の鳴動列が仕様どおりで、最後が終了時刻に一致すること
- 可変間隔で `startInterval == endInterval` のとき、等間隔の結果と完全に一致すること
- 間隔が1分を下回らないこと
- `HARD` のとき、進捗に応じて問題数が1〜3問に増えること
- 二度寝チェックの時刻が「範囲の最後の鳴動の停止時刻 + 待ち時間」であること
- 「タームを終了」を実行したセッションでは二度寝チェックが行われないこと
- 起床記録の集計（何回目で起きたか、所要時間、緊急停止の割合）

## 実機検証

実機へインストールして確認する。手順は `docs/DEVICE_TEST.md` に置く。

画面操作の自動化にGoogleのARTEMISを検討したが、実行するたびにLLMのAPI利用料が
かかるため見送った。実機の画面確認は `adb exec-out screencap` で行い、
画面の操作は Compose UIテスト（`app/src/androidTest/`）と手動で確認する。

実機UIテストは単体テストの実行ではコンパイルされない。`app/src/main/` の型を変えたときは
`./gradlew :app:compileDebugAndroidTestKotlin` も通すこと。一度、これを忘れて
実機確認ができない状態のままcommitしたことがある。

## 作らないもの

| 項目 | 理由 |
|---|---|
| 世界時計 | 主役から遠い。旧版のコードごと削除する |

| クラウド同期・アカウント | 通信しない方針と矛盾する |
| Wear OS対応 | 対象外 |
| スクリーンセーバー | 対象外 |
| ロック画面ウィジェット | 端末依存が大きい。今回は作らない |
| 将来用の抽象化層、複数実装のないinterface | 必要になってから作る |
