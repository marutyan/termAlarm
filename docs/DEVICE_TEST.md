# 実機確認の項目

対象端末: Pixel 10 Pro / Android 17 / API 37

`🔴` は必ず確認する。ここが通らなければリリースできない。

## 🔴 鳴動が確実に起こること

| 項目 | 確認方法 | 結果 |
|---|---|---|
| Doze中に鳴る | `adb shell dumpsys deviceidle force-idle` でDozeへ入れ、予約時刻を待つ | 未実行 |
| 予約時刻に鳴る | 2分後のアラームを仕掛けて待つ | **合格** 14:09:00の予約に対し14:09:06に鳴動 |
| 音が実際に出る | 端末の音を聞く | **合格** `USAGE_ALARM`で再生。利用者が音を確認 |
| 鳴動中に次回を予約 | 鳴動中に`dumpsys alarm`を見る | **合格** 14:09の鳴動中に14:10を予約済み |
| マナーモードで鳴る | サイレント／バイブのみに設定して鳴らす。`USAGE_ALARM` なので鳴るはず | 未実行 |
| ロック画面の上に出る | 画面ロック状態で鳴動時刻を迎える | 未実行 |
| 全画面で出る | 通知バーに留まらず、鳴動画面が前面に出ること | 未実行 |
| 再起動後も鳴る | 予約後に端末を再起動し、予約が復元されること | 未実行 |

# 記録: Android 17 の AudioHardening について

鳴動時のログに次が出る。

```
AudioHardening background playback would be muted for com.marutyan.termalarm,
level: full, reason: 4, usage: USAGE_ALARM
```

これは「バックグラウンド再生であれば消音する対象だった」という記録で、実際には消音されていない。
2026年9月2日の実機確認で、音が鳴ることを利用者が確認した。

純正の時計アプリ（`com.google.android.deskclock`）にも同じログが出るため、この端末の
新しい制限に共通して記録されるものと判断する。

**ただし、フォアグラウンドサービスとして正しく動いていることが前提**である。
サービスのフォアグラウンド化に失敗すると、このログのとおり実際に消音される可能性がある。
鳴動の経路を変更した場合は、このログではなく実際に音が出るかで判断すること。

# 記録: 検証中の再インストールに注意

実機で鳴動を待っている間に別の作業でアプリを再インストールすると、
`killDueToPackageUpdate` でプロセスが終了し、予約も消える。
鳴動の検証中は他の作業でインストールしないこと。
