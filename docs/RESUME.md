## 2. 決まっていること

### 時計タブ

**世界時計はやめる。** アナログ／デジタルを切り替えられる、秒まで見える大きな時計にする。
都市の追加・削除・並べ替え、時差の表示、天気はすべて作らない。

（すでに実装した世界時計のコードが `main` にある。作り直しで置き換える）

### 天気を入れない理由

純正の世界時計には気温が出るが、**外部から取得する手段がない**。

純正の天気アプリ（`com.google.android.apps.weather`）が公開している入口は
`FileProvider` とバグ報告用の2つだけで、`exported=true` の要素が1つもない。
純正時計が天気を出せるのはGoogle製アプリ同士の連携によるもので、署名が一致しないと通らない。

外部のAPIを使えば実装できるが、通信と位置情報が必要になり、「情報を集めない・通信しない」
というこのアプリの性格とPlayの申告が変わる。利用者の判断で入れないことにした。

### 下部ナビは4タブのまま

純正は5タブだが「おやすみ時間」は入れない。Digital Wellbeingと連携する機能で、
外部アプリからは同じことができない。

### 設定画面は13項目すべて作る

いまアプリに**設定画面が存在しない**。これは純正を置き換えるうえで大きな欠落。

作るもの（`docs/OFFICIAL_SETTINGS.md` に詳細）:

- アラーム7項目（解除の操作／消音までの時間／スヌーズの長さ／音量／徐々に音量を上げる／音量ボタンの動作／週の始まり）
- 時計3項目（スタイル／秒を表示／日付と時刻の変更）
- タイマー3項目（音／徐々に音量を上げる／バイブレーション）

作らないもの: アラームの同期、ペア設定済みデバイス、アダプティブアラーム（いずれもGoogleアカウント連携が前提）、
自宅の時計と自宅タイムゾーン（世界時計をやめたため）、温度単位（天気がないため）、スクリーンセーバー。

## 4. 録画がうまくいかなかった件

純正の動きを録画しようとしたが、取り出した動画が壊れていた（`moov atom not found`）。

原因は `adb pull` を録画の完了前に実行したこと。`screenrecord` はファイルを閉じるまで
メタデータを書かないため、途中で取り出すと再生できない。

**再開時に録画するなら**、`--time-limit` の秒数だけ確実に待ってから `adb pull` する。
フレームの取り出しには `uv run --with opencv-python-headless` が使える（環境を汚さない）。
`ffmpeg` は入っていない。

## 7. 作業の進め方についての注意

### 複数の担当を並列で動かすとき

**必ず `git worktree` で作業ツリーを分ける。** 同じディレクトリで並列に動かすと、
各自の `git checkout` が互いのブランチを奪い合い、コミット前の成果が失われる（実際に起きた）。

```sh
git worktree add -b feature/xxx /path/to/separate/dir origin/main
cp local.properties /path/to/separate/dir/   # SDKのパスが要る
```

### 実機テストは並列にできない

1台しかなく、パッケージ名が同じなので同時にインストールできない。
実装とJVM単体テストは並列、実機テストは順番に流す。

### データベースのバージョン

テーブルを追加したら**必ずバージョンを上げてMigrationを書く**。未リリースでも開発端末には
前の版のDBが残っているため、据え置くとテーブルが作られず機能しない（実際に起きた）。
移行は1つずつ順に並べる。飛び番の経路を書くと追えなくなる。

現在のバージョンは4（1→2 タイマー / 2→3 ストップウォッチ / 3→4 世界時計）。
世界時計をやめるなら、テーブルを消すか残すかの判断が要る。

### コードの圧縮

Activity・Service・BroadcastReceiver はManifestから名前で参照されるだけで、
コード上の呼び出しがないため圧縮で削除される。`app/proguard-rules.pro` で残しているが、
新しく追加したときは指定漏れに注意。`./scripts/release.sh verify` が照合する。

### 実機の操作

`adb shell input tap` と `input swipe` は使わない。座標がずれて利用者の他のアプリを
誤操作する事故が起きた。画面操作が要る検証はCompose UIテストで書く。
スクリーンショットは撮影前に `adb shell dumpsys window | grep mCurrentFocus` で
前面のアプリを確かめる。
