# 純正の仕様（2026年9月5日、利用者提供のスクショから）

## タイマー

### 追加画面はテンキー

**時分秒のステッパーではない。** 電卓のようなテンキーで入力する。

- 上部に `00h 00m 00s` と表示。入力した数字が右から詰まる
- 3列×4行のテンキー（1〜9、00、0、削除）。**キーは円形**
- 下に「×」（取消）と「▶」（開始）。開始は入力があるまで暗い

### 停止中のカード

- 円は**輪郭だけ**で、中に残り時間
- 右側に**再生ボタンのみ**（縦に1つ）

### 動作中のカード

- リングが減り、**先端に小さな丸**が付く
- 残り時間が **`57`** のように単位なしの数字だけになる（1分未満のとき）
- 数字の下に**リセットのアイコン**（円形の矢印）
- 右側に**上下2つのボタン**。上が `+1:00`（枠だけ）、下が一時停止（塗り）

**動作中と停止中でボタンの数が変わる。** 停止中は1つ、動作中は2つ。

## ストップウォッチ

### 初期状態

- `00:00.00`。文字は**地に近い灰色**（まだ動いていないことを示す）
- 操作は**「開始」1つだけ**。画面の中央より少し下に置かれ、**大きい**
- リセットとラップは**出さない**

### 動作中（ラップなし）

- 経過時間が明るい色になる
- 操作は**「停止」「リセット」「ラップ」の3つ**
- 停止だけサーモン色で目立たせる

### ラップを刻んだ後

- ラップのカードが**横に並ぶ**。3件までは矢印なし
- 4件以上で右上に**左右の矢印**が出る
- **最新のラップが色付き**（オレンジ）で強調される
- 各カードは3行（周回数 / そのラップの時間 / その時点の合計）
- **操作ボタンの位置は変わらない**。ラップが増えても下がらない

## 通知

利用者が撮影した純正の通知（2026年9月5日）から読み取った。

### タイマーの鳴動中
1つの通知にまとめられ、次の要素を持つ。

- 左に丸いアイコン（砂時計）
- 「時計」（アプリ名）と「タイムアップ」の2行
- 右に大きく `−00:07`。鳴ってからの経過時間で、マイナスが付いて伸びていく
- 下にボタン2つ「停止」「1分追加」。枠線だけのピル型で横に並ぶ

数字は通知の時計機能（Chronometer）で数えている。1秒ごとに通知を作り直して
数字を書き込むのではなく、終わる時刻を渡して端末側に数えさせている。

### ステータスバー
タイマーが動いている間、ステータスバーの左に丸いチップが出る。
砂時計のアイコンと残り時間（`00:44`）が入る。

### 純正が使っている仕組み

実機で純正の通知の中身を調べた（`adb shell dumpsys notification --noredact`）。

```
pkg=com.google.android.deskclock
channel=Timers v2
flags=ONGOING_EVENT|LOCAL_ONLY|PROMOTED_ONGOING
vis=PUBLIC
template=android.app.Notification$MetricStyle
```

読み取れること。

| 項目 | 値 | 意味 |
|---|---|---|
| `PROMOTED_ONGOING` | 立っている | ステータスバーへ出す扱いになっている |
| `LOCAL_ONLY` | 立っている | この端末の中だけで出す |
| `vis=PUBLIC` | | ロック画面でも中身を隠さない |
| `MetricStyle` | | 残り時間を端末側に数えさせる仕組み |

`MetricStyle` は Android 17 で使えるようになった。
`Notification.Metric.TimeDifference.forTimer(ゼロになる時刻, 書式)` に
「残り時間が尽きる時刻」を渡すと、端末が数を数える。
アプリが1秒ごとに数字を書き込む必要がなく、ゼロを過ぎると自動でマイナスへ伸びる。

次を揃えると、通知の見た目は純正と同じになる。

1. 種類が `CATEGORY_STOPWATCH`（`CATEGORY_ALARM` では対象外）
2. `setRequestPromotedOngoing(true)` を呼ぶ
3. `MetricStyle` で残り時間を渡す

ただし `PROMOTED_ONGOING` のフラグは立たず、ステータスバーのチップは出ない。
純正の通知には `FOREGROUND_SERVICE` の印が無く、こちらには有る。この違いが残る。
純正はサービスと通知を切り離しているとみられる。

`setColorized(true)` も試したが、フラグは立たず、
かわりに `FOREGROUND_SERVICE` の印が消える副作用だけが出たため戻した。

### 純正のサービスの使い方（純正のコードを読んで分かった）

純正の `TimerService` は、`com.android.deskclock.action.FIRE_TIMER` 以外の呼び出しを
「予期しない」として記録する。つまり **鳴ったときにしか起動しない**。

動作中はサービスを持たず、通知を1回出すだけ。残り時間は MetricStyle が数えるため、
1秒ごとに通知を作り直す必要がない。

このアプリも同じ作りへ変えた（2026年9月5日）。

| | 前 | 後 |
|---|---|---|
| 動作中 | 1秒ごとに更新するサービスが常駐 | 通知だけ。サービスなし |
| 鳴動中 | 同じサービス | 鳴らすためだけのサービス |
| 期限の判定 | サービスの1秒ごとの見回り | AlarmManagerの予約 |

### 純正が使っている、見つけにくい指定

純正のコードから見つけた。どれも通知の見た目に効く。

```java
extras.putBoolean("android.app.preferSmallIcon", true);   // 丸アイコンにsmallIconを使う
extras.putBoolean("android.requestPromotedOngoing", true);
setShowWhen(false);
```

`preferSmallIcon` を入れないと、通知の丸いアイコンがアプリのアイコンになる。
純正のように砂時計を出すにはこの指定が要る。

### ステータスバーのチップ（解決済み）

`PROMOTED_ONGOING` のフラグが立たず、長く原因が分からなかった。
公式の資料（developer.android.com「Create live update notifications」）に答えがあった。

**マニフェストへ権限の宣言が要る。**

```xml
<uses-permission android:name="android.permission.POST_PROMOTED_NOTIFICATIONS" />
```

これは実行時に許可を求める種類の権限ではないため、宣言するだけでよい。
宣言が無いと、`setRequestPromotedOngoing(true)` を呼んでもフラグが立たない。

そのほかの条件。

| 条件 | 内容 |
|---|---|
| 見出し | `setContentTitle` が必須。省くと対象外になる |
| 形 | Standard / BigText / Call / Progress / Metric のいずれか |
| 進行中 | `setOngoing(true)` |
| チャンネル | 重要度が `IMPORTANCE_MIN` でないこと |
| チップの文字 | `setShortCriticalText`、`setWhen`(2分以上先)、Chronometer のいずれか |

**やってはいけないこと**（資料に明記されている）。

- `setColorized(true)`
- `setCustomContentView`（RemoteViews）
- `setGroupSummary(true)`

以前 `setColorized(true)` を試して効果が無かったのは、禁止されていたため。

チップの幅は96dpまで。収まらない場合はアイコンだけになる。
`setShortCriticalText` へ渡す文字は7文字ほどに収める。

確かめ方のAPIもある。

```kotlin
notification.flags and Notification.FLAG_PROMOTED_ONGOING != 0   // 昇格したか
notification.hasPromotableCharacteristics()                       // 条件を満たすか
NotificationManagerCompat.from(context).canPostPromotedNotifications()  // 投稿できるか
```

利用者の設定画面へは `Settings.ACTION_MANAGE_APP_PROMOTED_NOTIFICATIONS` で飛べる。

## 純正のコードから読めること・読めないこと

`jadx` で純正のAPKを丸ごと逆コンパイルした（8680ファイル）。分かったのは次のとおり。

### 読める

- **通知の作り方**。`Notification` はプラットフォームのAPIなので名前が残る。
  `MetricStyle`、`requestPromotedOngoing`、`preferSmallIcon` はこれで見つけた。
- **サービスの使い方**。`TimerService` が `FIRE_TIMER` のときだけ起動することが読めた。
- **マニフェスト**。受け付けるIntentや権限の一覧。

### 読めない

- **画面の寸法**。UIは完全にJetpack Composeで書かれており、
  クラス名も数値も難読化で潰れている。`androidx.compose.ui.unit.Dp` を扱うクラスが
  1つも見つからず、`82.0f` のような値も残っていない。
- **動きの秒数や曲線**。同じ理由で読めない。

### 結論

**寸法は実機から測るしかない。** `adb shell uiautomator dump` で
要素ごとの位置と大きさが取れるので、それを唯一の物差しとする。
画像から目分量で測ると外す（実際に2回外した）。


## 実機の画面を一時的に狭めるときの注意

分割画面での崩れを確かめるため `wm size` を使うことがある。
**このとき、画面の密度も一緒に変わる。** `wm size reset` はサイズしか戻さない。

必ず両方を戻すこと。戻し忘れると、端末全体の文字とアイコンが小さいままになる。

```sh
# 前に記録しておく
adb shell wm size
adb shell wm density
adb shell settings get secure display_density_forced

# 狭める
adb shell wm size 1080x1200

# 終わったら必ず両方戻す
adb shell wm size reset
adb shell wm density reset

# 確かめる（display_density_forced が空になっていること）
adb shell wm density
adb shell settings get secure display_density_forced
```

`font_scale`（文字の大きさ）は利用者の設定なので、決して触らない。

### この端末の設定（戻すときはこの値にする）

| 項目 | 値 |
|---|---|
| 画面の密度 | **356**（表示サイズ「最小」。物理値の420ではない） |
| 画面の大きさ | 1080x2410 |
| 文字の大きさ | 0.85 |

**`wm density reset` を使ってはいけない。** 物理値の420に戻ってしまい、
利用者が選んでいる「最小」から外れる。戻すときは値を直に指定する。

```sh
adb shell wm density 356
```

一度これを間違えて、端末全体の表示を2回大きくしてしまった。
変えたら最後は必ず356へ戻すこと。

## 純正のアラーム通知（2026年9月6日、実機のdumpsys notificationで実測）

純正の時計アプリは、アラームについて2種類の通知を出す。

### 鳴る前:「次のアラーム」

- チャンネル: `Upcoming Alarms v2`、重要度3（画面の上へは降りてこない）
- タイトル「次のアラーム」、本文「3:45 (日)」
- 操作は1つだけ:「アラームを解除」
- `showWhen=false`、`vis=PUBLIC`、`timeout=PT72H`
- 複数あるときは `groupKey` でまとめ、`sortKey` に鳴動時刻の文字列（`2026-09-06 03:45:00.000`）を入れて鳴る順に並べる
- 鳴る2時間前から出る

### 鳴っている間:「アラーム」

- チャンネル: `Firing`、`category=alarm`
- flags: `ONLY_ALERT_ONCE|NO_CLEAR|FOREGROUND_SERVICE|HIGH_PRIORITY|LOCAL_ONLY`
- 畳んだ状態の本文は「3:31 (日)・スワイプすると停止します」
- 開くと操作が2つ:「スヌーズ」「ストップ」
- 端末を使っている最中は全画面ではなく、画面の上へ降りてくる形（heads-up）で出る

対応する文言の資源名は `upcoming_alarm` / `next_alarm_description` / `swipe_to_stop` /
`alarm_alert_snooze_text` / `alarm_alert_dismiss_text`。

### このアプリでの扱い

同じ2種類を同じ形で出し、時間帯で繰り返す事情として、どちらの本文にも
「4:45（日）・あと6回」のように残り回数を足し、操作へ「このタームを終了」を加えている。

### 通知の操作ボタンを右へ寄せることはできない

標準の型では、操作は必ず本文の下の行に横並びで置かれる。Android 17の
`Notification.Action.Builder.setStyleHint(STYLE_ICON_ONLY)` を指定しても、
この型では見た目が変わらないことを実機で確認した（文字のボタンのまま出る）。
右へ置くには通知の中身を自前で組む必要があり、端末の配色や文字サイズへの
追従を自分で作り込むことになるため採用しない。

なお畳んだ状態では操作の行自体が出ないため、通常の見え方は2行で収まっている。

## 純正のストップウォッチ（2026年9月6日、実機の画素から実測。密度356）

前に書いた「操作ボタンの高さ104dp」は、画面を一時的に狭めていたときの値で誤り。
密度を利用者の設定（356）へ戻して測り直した。

| 要素 | 実測 |
|---|---|
| 左右の余白 | 16dp |
| ボタンの幅 | 453dp（画面幅485dpから左右16dpを引いた残り） |
| 主ボタン（開始・停止）の高さ | 129dp |
| 副ボタン（リセット・ラップ）の高さ | 89dp |
| ボタンどうしの間 | 7dp |
| いちばん下のボタンから下部ナビまで | 96dp |
| 主ボタンの上端 | 画面上端から562dp |

色は端末のシステム色そのままで、`adb shell cmd overlay lookup android android:color/...` で読める。

| 場所 | 色 | システム色 |
|---|---|---|
| 停止（動作中） | `#F97758` | `system_error_dark` |
| 開始（未計測・一時停止中） | `#F5B68E` | `system_primary_dark`系 |
| リセット・ラップ | `#2C2519` | `system_surface_container_highest_dark` |

- 文字は「開始」と「停止」の2つだけ。一時停止から戻すときも「開始」と出す
- リセットとラップは同じ地の色。動作中でもリセットは押せる
- 経過時間は未計測・一時停止中だけ地に近い灰色にする

### Composeの動的配色はerrorだけ壁紙を反映しない

`dynamicDarkColorScheme()` が返す `error` は既定の淡いピンク（`#F2B8B5`）のままで、
端末の `system_error_dark`（この端末では `#F97758`）にならない。
純正はシステム色を使うため、同じ端末でも色が食い違う。
Android 14以降は資源から読めるので、テーマ側で読み替えている（`ui/theme/Theme.kt`）。
